# P25 Phase 1 on the Retevis C62

Status as of 2026-11-04: **P25 Phase 1 transmit and receive work on the C62.**
A real P25 subscriber radio decodes the voice, and `dsd-fme` decodes the same
transmission with zero IMBE/LCW errors.

Everything here lives on the N4IRS fork only:
`github.com/N4IRS/OpenRTX`, branch **`c62-m17-plus`**.

| | |
|---|---|
| Build dir | `build.p25test` |
| `zephyr.bin` | 423,664 B (flash 40.4 %), md5 `dad000d1…` (enhanced encoder, flashed and verified on air) |
| Commits | `8cedbd41` P25 Phase 1 support, `4f10feac` codec replay fix, `bf1a692a` level entry, `fc00dd3e` gain chain + FEC concealment, `719aab6f` TX audio shaping, enhanced encoder |

FM, M17 and P25 all build in the same image (`CONFIG_M17` + `CONFIG_P25` in
`platform/targets/c62/hwconfig.h`).

## 1. Operation

All P25 settings are **global**, not per channel: there is no `p25Info_t` in
`channel_t` yet (see `docs/chirp-cps-feasibility.md`).

P25 Settings menu:

| Item | Value used here | Notes |
|---|---|---|
| `DMR Id` (source) | `3112138` | Unit ID sent in the LCW |
| `Dst Id` | `3166` | Talkgroup |
| `NAC (hex)` | `0x293` | Entered and shown in hex. dsd-fme prints it without the prefix, as `293` |
| `RX Level` | `100` | Baseband input gain; `P25_IO` resets it to 100 if stored as 0 |
| `TX Level` | `160` | Baseband output amplitude; `P25_IO` resets it to 160 if stored as 0 |
| `RX Invert` | `ON` | **Required on the C62 to lock** |
| `TX Invert` | `ON` | Compensates the BK4819 mic-path audio → deviation inversion |

### Editing RX / TX Level

`ENTER` on the item opens a number-entry screen showing the current value.

- type the value with the keypad (3 digits, 1…255)
- or step it with `UP` / `DOWN` (±1)
- `ENTER` saves, `ESC` cancels

The value is written to `settings.p25_tx_level` / `p25_rx_level` and persisted
in the CRC-protected settings record by `nvmem_C62.c`.

`TX Level` is a plain baseband scale factor: `P25TX.cpp` multiplies the IMBE
output by `m_txLevel * 128` in Q15, so 160 ≈ 0.625 of full scale. 160 is the
value verified on air; much higher values can clip the deviation.

### TX polarity

P25 symbol levels in `P25TX.cpp` follow TIA-102.BAAA:

```
P25_LEVELA = -1260   P25_LEVELB = -420   P25_LEVELC = +420   P25_LEVELD = +1260
```

`dsd-fme` must report `+P25p1`. A `-P25p1` lock means the levels are inverted.

## 2. Verifying a transmission

Live decode with the RTL-SDR (the radio transmits on 446.900 MHz, NAC `0x293`,
which dsd-fme prints as `293`):

```bash
export LD_LIBRARY_PATH=/tmp/mbelib:/srv/Backup/NUC/rtl-sdr/build/src
/srv/WorkSpace/reference-code/dsd-fme/build/dsd-fme \
  -i rtl:0:446.9M:40:0:12:0:2 -o null -Z -c /tmp/dibits.bin
```

`-o null` is required (no audio device on the test host). Gain 40 is enough
for a live decode; 29.7 dB was starved. Decode is insensitive to gain between
20 and 49.6 dB once the baseband is correct.

A good key-up looks like:

```
Sync: +P25p1  NAC/CC: 293;  HDU
HDU  ALG ID: 0x80 KEY ID: 0x0000 MI: 0x0000000000000000
Sync: +P25p1  NAC/CC: 293;  LDU1
IMBE 040CFD7BFB7DF27B3D9E45 err = [0] [0]
LCW Circuit Priority 0 Group Voice Channel User - Group 3166 Source 3112138
```

Checklist:

- every sync is `+P25p1`;
- the **first** sync of a key-up is followed 432 symbols later by the second
  one (that frame is the 216-byte HDU followed by one 9-byte half-buffer of
  padding), then all spacings are **864 symbols / 216 bytes**;
- HDU decodes at the start of the transmission;
- LCW FEC errors are 0, IMBE words mostly `err = [0] [0]`;
- no `duid:EE` (that is dsd-fme's NID BCH failure, `dsd_frame.c:408-413`).

Offline analysis from a raw IQ capture: `rtl_sdr -f 447150000 -s 2400000
-g 40.2 -n <samples> out.iq8`, then `iq2wav.py` draws an audio WAV for
`dsd-fme -i file.wav`.

## 3. What was broken

### 3.1 Symbol polarity

The P25 TX symbol levels were the exact inverse of TIA-102.BAAA, so
`dsd-fme` locked `-P25p1` and a real radio did not unmute. Levels are now
negated (`-1260/-420/+420/+1260`), verified on air.

### 3.2 Codec replaying baseband halves

Symptom: frame syncs every **1152** symbols instead of 864, a second sync
72 symbols (18 bytes) into each frame, dsd-fme finally giving up with
`duid:EE`.

Root cause: the producer generated a complete frame (4320 samples) before
handing anything to the codec. The CSK6 audio worker (`csk6_codec.c`,
`output_sample()`) wrapped the TX double buffer and replayed a half whenever
the producer missed a boundary. Each replay duplicated 72 symbols, stretching
every frame by 4/3.

Fix:

- `P25TX.cpp` drains the codec per byte (`update_tx(20, false)`);
- `P25_IO::update_tx()` gained a `flush` flag so the final partial half is
  pushed instead of waiting for a boundary;
- the TX half-buffer was grown from 180 to 720 samples
  (`P25_TX_HALF_SAMPLES`).

Evidence: the only exact repetition lag in the C62 dibit stream was 72
symbols (≈20 % of all symbols); the offline harness with a stubbed
`update_tx()` showed none.

### 3.3 The HDU was not broken

An `duid:EE` frame at key-up was initially blamed on the HDU builder. It was
the same framing bug: no capture before the fix had ever included the start of
a transmission. Once captured, the radio's HDU is byte-identical to the
known-good offline harness HDU (NID `29 30 0E CE D7 7E 00 70`); only the final
padding byte differs (`00` vs `02`). It decodes as
`HDU ALG ID: 0x80` right before the first LDU1.

Note that an HDU is optional for unencrypted P25 group calls — the reference
radio unmutes even without it — but it is now sent correctly.

### 3.4 Baseband level menu

The P25 RX/TX level entries opened an edit screen that never initialised the
input buffer, ignored keypad digits, displayed no value and ignored `ESC`.
The only working gesture was DOWN-then-ENTER (decrement by 1, blindly).
`ui.c` now drives the same numeric-entry path as the ID fields: current value
visible, digits accepted, `UP`/`DOWN` stepping, `ENTER` commits (clamped
1…255), `ESC` cancels.

The `NAC` entry was labelled `NAC (dec)` although it is parsed with base 16
and displayed as `0x%03X`; the label now reads `NAC (hex)` to match.

### 3.5 Audio quality: gain chain and FEC concealment

The vocoder was compared with the other IMBE implementations in
`reference_code`:

| Reference | Finding |
|---|---|
| `g4klx_imbe_vocoder/src/lib` | Same Pavel Yazev engine: `ch_decode`, `sa_decode`, `sa_enh`, `uv_synt`, `v_synt` are identical apart from class names. |
| `op25/.../lib/imbe_vocoder` | Same engine, same result. |
| `dvmhost/src/vocoder/imbe` | Same engine; encoder defaults match ours (`d_gain_adjust = 0`, enhancement off). |
| `MMDVM-Host/P25Audio.cpp`, `AMBEFEC.cpp` | Same algorithms as ours (already established). |

So the DSP core is reference-grade; the defects were in how it was driven.

A host harness (150 frames of speech encoded and decoded with the vendored
engine) measured the decoder output at **peak −3.1 dBFS, RMS −22.5 dBFS**.
That is the level the converter expects, and both dvmhost and op25 feed it to
the DAC at unity gain.

- **RX gain.** The decoder was multiplied by 32, with a comment claiming M17
  applies ×2 to codec2 output. That ×2 exists only on `PLATFORM_MD3x0`; on the
  C62 the M17 path is unity. Measured clipping at ×32 is **24 % of all
  samples**; ×2 still clips 0.18 % of peaks. The RX path now uses unity
  (`rxGain` in `imbe_audio_codec.cpp`, applied through a saturating helper).
  If the speaker is too quiet after evaluation, raise `rxGain` to 2 and
  expect occasional peak clipping.
- **TX gain.** The microphone path multiplied by 8 and then by 4, both into
  `int16_t` without saturation: any sample above 2047 wrapped (sign
  inversion) in the second multiply. It is now a single saturating
  `CONFIG_MIC_GAIN` (13 on the C62, the same value the M17 codec path uses).
  Deviation remains controlled by `TX Level`, not by overdriving the vocoder.
- **FEC concealment.** `CP25Audio::process()` returns the number of corrected
  bits per LDU; the return value used to be discarded. If it exceeds **124**
  (dvmhost's `DEFAULT_SILENCE_THRESHOLD`), all nine voice frames are replaced
  with `P25_NULL_IMBE` instead of being synthesised as a noise burst. The
  null frame decodes to digital silence.
- **State buffers.** `imbe2_api.cc` now asserts at compile time that the
  encoder (6,676 B) and decoder (1,932 B) still fit the hand-sized buffers in
  `imbe_vocoder_api.h` (8,704 / 2,048 B).

### 3.6 Transmit audio shaping

After the gain and concealment fixes, receive audio on the C62 was good but
transmit audio still sounded muffled on a real P25 subscriber.

**What was measured.** A 35 s transmission was captured with
`dsd-fme -w out.wav`; the IMBE frames decoded with `err = [0][0]`, so the
link was clean and the problem was purely audio. The captured speech had
**36 % of its energy below 500 Hz** and a spectral centroid of 953 Hz, i.e.
the vocoder was coding a boomy signal.

Two measurement routes were rejected as invalid:

- **FM capture as a microphone reference.** In voice mode the BK4819 applies
  pre-emphasis, while P25 and M17 run with `AUDIO_BYPASS`
  (`radio_C62.cpp`), so the FM spectrum is not the signal the encoder sees.
- **Serial-console dumps of the encoder input.** The programming cable
  disturbs the microphone and receive audio; with it plugged in the encoder
  input measured only ±3 LSB of noise, which is not what a working
  microphone produces. All audio evaluation must be done with the cable
  unplugged. (Consistent with this, raising the ADC microphone gain
  (`C62_ADC_MIC_GAIN_A/D`) was tried and produced no usable result; the
  gains are back at their original 6/10 dB.)

**What ships.** A second-order Butterworth high-pass at 200 Hz ahead of the
microphone gain in the IMBE encoder path (`imbe_audio_codec.cpp`): RBJ
biquad at 8 kHz, −3 dB at 200 Hz and −24 dB at 50 Hz. Rumble that cannot be
coded by IMBE is removed before the spectral analysis, so the coded spectrum
is closer to speech. On air the result is noticeably clearer.

**What was rejected.** A high shelf was also tried, because this microphone
rolls off towards the top of the band:

| Shelf | Result on air |
|---|---|
| +5 dB at 1.8 kHz | Clearer, but harsh |
| +2.5 dB at 1.8 kHz | Still harsh |
| none (high-pass only) | Clear, not harsh |

The shelf is therefore not in the build. Do not raise it without an on-air
A/B: the harshness is audible well before the measurement suggests it should
be.

The shaping applies to the P25 encoder only; the FM and M17 paths are
unchanged.

### 3.7 Enhanced encoder mode

The vendored encoder has an optional enhanced mode (`imbe2_encoder_set_enh`,
exposed as `vocoder.set_enh()`); dvmhost leaves it off. It changes three
things:

- **Pitch tracking** becomes "leashed continuity": among candidates whose fit
  is within `ENH_LEASH` (0.024) of the best, it prefers the previous frame's
  pitch. This is meant to remove jitter between near-equal candidates and
  octave errors.
- **Voicing thresholds** move from 0.5625/0.45 to 0.62/0.40, i.e. a bias
  towards voiced frames.
- **A spectral noise gate**: a 3 s windowed minimum of frame power, opening
  when energy exceeds 25 × the minimum and closing below 4 ×, muting closed
  frames before analysis.

**Offline check** (encoder only, 8 kHz IMBE round-trip, no radio):

| Case | Result |
|---|---|
| 3 s continuous speech | RMS 2440 → 2354, centroid 741 → 740 Hz, no gated frames |
| speech, 2 s room noise, speech | noise 114 → 111, no speech frames muted |
| quiet speech (−20 dB) | 128 → 125, not muted |
| 8 s quiet speech, no background noise | gate never closes (no floor to measure) |
| 5 s noise, then a loud word | re-opens within one frame: −2.8 dB at 20 ms, +1.0 dB at 40 ms |

Two findings worth keeping:

- **The gate is inert for the first 3 s of a transmission.** The statistics
  window starts zeroed and is only updated once its minimum exceeds zero, so
  nothing is decided until the window has filled. Test cases shorter than
  that show no effect at all.
- **Suppression is only ~10 dB in decoded level**, not silence: the decoder's
  idle floor still has energy after a muted frame. Do not expect it to remove
  hiss dramatically.

**On air** the result was judged **better than the previous build**: onsets
are intact, quiet speech does not drop out, and speech sounds cleaner
overall. Since the measurable part of the change is a wash, the gain comes
from the perceptual pitch behaviour; the noise gate is a small, safe side
effect. Note that this verdict is a subjective A/B by the developer, not a
measured improvement — it is worth re-checking against `txEnh = 0` before
changing anything else in the encoder.

`txEnh` in `imbe_audio_codec.cpp` selects the mode and is applied once at
encoder-thread start; `txEnh = 0` restores the previous behaviour exactly.

## 4. Known limitations

- P25 **Phase 1** only: no Phase 2, no trunking, no encryption (ALG ID 0x80 =
  unencrypted is hard-coded in the HDU/LDU).
- P25 configuration is global, not per channel (see the CPS notes).
- `TX Level` is an amplitude, not a calibrated deviation control; use 160
  unless a deviation meter says otherwise.
- The receive path needs `RX Invert = ON` on this board because of the BK4819
  discriminator polarity.
- P25 RX audio is at unity decoder gain (reference behaviour). If it is too
  quiet on the C62 speaker, raise `rxGain` in `imbe_audio_codec.cpp`; 2 is
  the practical maximum before peaks start clipping.
- The transmit side uses Pavel Yazev's IMBE encoder, not a DVSI vocoder. It is
  intelligible but will not match a commercial subscriber's audio.
- Audio evaluation must be done with the programming cable **unplugged**: with
  it attached the microphone and receive audio are disturbed, which makes
  every audio test invalid (see 3.6).
